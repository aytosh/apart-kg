# Техническое задание (ТЗ)
## Мобильное приложение аренды и продажи недвижимости

**Версия:** 1.0  
**Дата:** 2025

---

## 1. Общие сведения

### 1.1 Название проекта
Мобильное приложение для аренды и продажи недвижимости (квартиры, дома, офисы).

### 1.2 Цели проекта
- Предоставить пользователям единую площадку для поиска и размещения объявлений об аренде и продаже недвижимости.
- Обеспечить удобный поиск по фильтрам, карте и контакт между арендаторами/покупателями и арендодателями/продавцами.
- Монетизация за счёт платного размещения объявлений, комиссий или подписок для агентов.
- **Бенчмарк и конкуренция:** в целевом регионе (Кыргызстан) доминирует платформа **house.kg**. Цель продукта — **как минимум сравняться** с house.kg по удобству и функционалу, **по возможности превзойти** их за счёт более современного UX, скорости работы приложения и дополнительных возможностей (см. п. 1.5).

### 1.3 Целевая аудитория
- **Арендаторы** — поиск жилья/офиса в аренду.
- **Арендодатели и продавцы** — размещение объявлений (частные лица и агенты).
- **Покупатели** — поиск объектов для покупки.
- **Агенты и застройщики** — массовое размещение и продвижение объявлений.

### 1.4 Регион и языки
- **Регион запуска:** Кыргызстан (все области: Чуйская, Иссык-Кульская, Таласская, Нарынская, Джалал-Абадская, Ошская, Баткенская, г. Бишкек, г. Ош и др.).
- **Языки:** русский, кыргызча, английский (на паритете с house.kg и для расширения аудитории).
- **Локализация:** сом (KGS), форматы дат и адресов по региону.

### 1.5 Бенчмарк: house.kg (обязательный уровень и точки превосходства)

Чтобы **приравняться или обогнать** house.kg, в продукте должны быть реализованы следующие возможности (уровень house.kg) и по возможности улучшены:

| Функция у house.kg | Требование к нашему приложению | Превосходство (где обгоняем) |
|--------------------|--------------------------------|------------------------------|
| Расширенные фильтры (цена, регион, тип, комнаты, этаж, площадь, год постройки) | Реализовать не хуже: все перечисленные фильтры + тип отопления, интернет, высота потолков | Более быстрая работа фильтров, сохранённые поиски с push при появлении новых объявлений |

| Раздел «Новостройки» / застройщики | Раздел или фильтр «Новостройки», привязка к застройщикам/ЖК | — |

## 2. Функциональные требования

### 2.1 Роли пользователей

| Роль | Описание | Основные возможности |
|------|----------|----------------------|
| Гость | Неавторизованный пользователь | Просмотр каталога, фильтрация, просмотр карточки объекта, переход к регистрации/входу для контакта |
| Пользователь (арендатор/покупатель) | Зарегистрированный пользователь | Всё для гостя + избранное, заявки/чат с владельцами, уведомления, личный кабинет |
| Владелец/агент | Размещает объявления | Всё для пользователя + создание/редактирование/деактивация объявлений, управление заявками, статистика просмотров |
| Администратор | Управление платформой | Модерация объявлений и пользователей, настройки системы, отчёты |

### 2.2 Модули и функции

- **Каталог объектов**
  - Список объявлений с превью (фото, цена, адрес, краткое описание).
  - Типы объектов (паритет с house.kg): квартира, дом, коммерческая недвижимость (офисы и др.), комната, участок, дача, паркинг/гараж.
  - Фильтры: тип объекта, аренда/продажа, цена (мин–макс), площадь, количество комнат (1–6+), этаж/этажность, район/область/город, год постройки, наличие мебели, тип отопления, интернет, высота потолков, рассрочка, обмен, дата публикации; опционально — «Срочно».
  - Сортировка: по дате, по цене, по релевантности.
  - Поиск по тексту (название, описание, адрес).
  - Раздел или фильтр «Новостройки» (привязка к застройщикам/ЖК).

- **Карта**
  - Отображение объектов на карте (пины/кластеры).
  - Переход к карточке объекта по тапу на пин.
  - Масштабирование и перемещение карты.

- **Карточка объекта**
  - Галерея фото (свайп), при наличии — видеообзор; основное описание, цена, площадь, адрес.
  - Характеристики: комнаты, этаж/этажность, мебель, тип отопления, интернет, высота потолков, год постройки; опции «рассрочка», «обмен», «срочно».
  - Контакт: кнопка «Написать» / «Позвонить» одним касанием (для авторизованных или с напоминанием войти).
  - Добавление в избранное.
  - Поделиться объявлением (мессенджеры, соцсети).

- **Избранное**
  - Сохранённые объявления, удаление из избранного.
  - Уведомление об изменении цены или снятии с публикации (опционально).

- **Личный кабинет**
  - Профиль: имя, аватар, телефон, email (редактирование).
  - Мои объявления (для владельца/агента): черновики, активные, архив.
  - Мои заявки / диалоги.
  - Настройки: уведомления, язык (если несколько).

- **Размещение объявлений**
  - Создание объявления: тип (аренда/продажа), категория (квартира/дом/офис/комната/участок/дача/паркинг-гараж), адрес (с автоопределением локации на карте), цена, площадь, описание, расширенные характеристики (этаж, год постройки, отопление, интернет и т.д.), опции рассрочка/обмен/срочно, фото с камеры или галереи (обязательно минимум 1), при необходимости — видео, контакты.
  - Редактирование и деактивация.
  - Черновики (сохранение без публикации).
  - Поднятие объявления в ТОП (через ЛК; бесплатно с лимитами или платный boost — по продуктовой модели).
  - Модерация: объявление может требовать проверки перед показом (по решению продукта).
  - Для агентств: бизнес-аккаунт / компания (несколько объявлений, брендирование).

- **Чат / заявки**
  - Для каждого объявления — диалог между пользователем и владельцем (или форма «отправить заявку» с уведомлением на email/в приложение).
  - Список диалогов, уведомления о новых сообщениях.
  - MVP: простой чат по объявлению без медиа (или только текст).

- **Уведомления**
  - Push: новые сообщения, одобрение/отклонение объявления, напоминания (опционально).
  - In-app: список уведомлений в ЛК.

### 2.3 Обязательные сценарии (критерии приёмки)

1. **Регистрация и авторизация**  
   Регистрация по email/телефону, вход, восстановление пароля, выход. Опционально: вход через соцсети (Google, Apple).

2. **Просмотр и фильтрация**  
   Гость или пользователь открывает приложение, видит каталог, применяет фильтры (тип, цена, район), видит список и карту, открывает карточку объекта.

3. **Подача заявки / контакт**  
   Пользователь на карточке объекта нажимает «Написать» или «Позвонить»; при необходимости сначала выполняется вход. Владелец получает уведомление и может ответить в чате.

4. **Создание и редактирование объявления**  
   Владелец/агент создаёт объявление (все обязательные поля, минимум одно фото), сохраняет черновик или отправляет на публикацию. После модерации (если включена) объявление отображается в каталоге. Владелец может редактировать и деактивировать объявление.

## 6. Backend и данные

### 6.1 API
- **Стиль:** REST или GraphQL [указать выбор].
- **Аутентификация:** JWT или OAuth 2.0; refresh token с ротацией.
- **Документация:** OpenAPI (Swagger) или аналог для всех публичных эндпоинтов.

### 6.2 Хранение данных
- **Пользователи:** профиль, контакты, настройки, токены push.
- **Объявления:** метаданные, статус (черновик/на модерации/активно/архив), связь с владельцем.
- **Медиа:** фото объявлений (внешнее хранилище — S3/Firebase Storage), ссылки в БД.
- **Чаты/заявки:** сообщения, связь с объявлением и пользователями.

### 6.3 Рекомендации по стеку
- **Быстрый старт:** Firebase (Auth, Firestore/Realtime Database, Storage, Cloud Functions для логики и уведомлений).
- **Гибкость и масштаб:** собственный backend (Node.js / Python) на AWS, GCP или другом облаке; БД (PostgreSQL/MongoDB), кэш (Redis при необходимости).

### 6.4 Характеристики сервера (инфраструктура)

Ниже — ориентиры для **собственного backend** (VPS/облако). При выборе Firebase часть нагрузки берёт на себя Google; требования к «серверу» минимальны (только настройка и мониторинг).

**Исходные допущения (из п. 3.4):**
- Старт: до ~10 000 активных пользователей в месяц, до ~50 000 объявлений.
- Год 1: рост до десятков тысяч пользователей и сотен тысяч объявлений; пиковые запросы — каталог, карта, карточка объекта, чат.

#### Вариант A: один сервер (MVP, экономичный старт)

| Компонент | Минимум | Рекомендуется | Комментарий |
|-----------|---------|----------------|-------------|
| **vCPU** | 2 | 4 | API + приложение; при росте — вынести БД отдельно |
| **RAM** | 4 GB | 8 GB | Запас под пики (поиск по каталогу, фильтры) и кэш в памяти |
| **Диск** | 40 GB SSD | 80–100 GB SSD | ОС, логи, приложение; БД лучше на отдельном томе или инстансе |
| **Сеть** | 100 Mbit/s | 1 Gbit/s | Исходящий трафик для API и отдачи превью (медиа — из S3/Storage) |

Подходит для запуска и первых месяцев при умеренной нагрузке. Базу данных (PostgreSQL) можно держать на том же сервере при 2–4 vCPU и 8 GB RAM; при росте — вынести на отдельный инстанс.

#### Вариант B: разделение приложения и БД (рекомендуется к концу первого года)

| Роль | vCPU | RAM | Диск | Комментарий |
|------|------|-----|------|-------------|
| **Сервер приложения (API)** | 2–4 | 4–8 GB | 20–40 GB SSD | Node.js / Python, несколько воркеров; за нагрузкой — масштабировать по горизонтали |
| **Сервер БД (PostgreSQL)** | 2–4 | 4–8 GB | 50–100 GB SSD | Отдельный инстанс; регулярный бэкап, при росте — больший диск и RAM |
| **Кэш (Redis)** | 1 | 1–2 GB | 5–10 GB | Сессии, кэш списков/фильтров; опционально на отдельном малом инстансе или на сервере приложения |

#### Вариант C: облачные managed-сервисы (без ручного администрирования серверов)

- **App:** развёртывание на AWS EC2 / GCP Compute / DigitalOcean Droplet или serverless (AWS Lambda, Cloud Functions) за API.
- **БД:** AWS RDS (PostgreSQL), Google Cloud SQL, DigitalOcean Managed DB — стартовый инстанс: 2 vCPU, 4 GB RAM, 50 GB SSD.
- **Кэш:** ElastiCache (Redis) или аналог — малый инстанс (1–2 GB RAM) или кэш в памяти приложения на старте.
- **Медиа:** не на «сервере», а в S3 / Firebase Storage / аналоге (уже учтено в расчёте расходов).

#### Рекомендации по этапам

| Этап | Нагрузка (ориентир) | Рекомендация |
|------|----------------------|--------------|
| **Запуск MVP** | до ~5–10k MAU, до ~30k объявлений | Один сервер 4 vCPU, 8 GB RAM, 80 GB SSD (приложение + БД) или managed БД + один app-сервер 2 vCPU, 4 GB |
| **Первый год (рост)** | до ~30–50k MAU, до ~100k+ объявлений | Разделить API и БД; API 4 vCPU / 8 GB (или 2 инстанса по 2 vCPU); БД 4 vCPU / 8 GB / 100 GB SSD; при необходимости добавить Redis |
| **Дальнейший рост** | 100k+ MAU | Горизонтальное масштабирование API, увеличение инстанса БД или репликация чтения, CDN для статики и превью |

**Дополнительно:** резервное копирование БД — минимум раз в сутки, хранение бэкапов отдельно от основного сервера. SSL (HTTPS) — обязательно (Let's Encrypt или сертификат от хостера). Мониторинг: доступность API, загрузка CPU/RAM, время ответа ключевых эндпоинтов (каталог, карточка объекта).
